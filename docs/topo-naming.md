# 形状の参照名エンジン (段階 1.5 / #2)

## 1. 調査: これまでの参照方式

| 参照元 | 保存形式 | 再接続の方法 |
|---|---|---|
| フィレット・面取り・溶接 (`EdgeRef`) | 中点・端点・種類・ボディの外接箱内の正規化位置 | カーネルで全エッジと距離スコアを比較 (`resolveEdges`)。結果の座標を `updatedRefs` で書き戻す |
| シェル・抜き勾配・厚み付け・プレス/プル・ねじ・分割 (`FaceRef`) | 中心・法線・種類・正規化位置 | 同上 (`resolveFaces`) |
| 面上のスケッチ・穴 | 面の平面をコピーして固定 (`SketchFeature.plane`) | **追従しない** (上流で面が動いても平面は元の位置のまま) |
| パターン | 元フィーチャの id | id なので壊れない (面・辺の参照ではない) |
| アセンブリ拘束 (`GeoRef.face/edge`) | 部品座標の中心・法線 | UI 側で距離 + 法線のスコア (`geoFromRef`) |
| PMI (`PmiRef`) | `FaceRef` / `EdgeRef` | UI 側で同じスコア (`mbd/resolve.ts`) |
| 図面寸法 (`GRef`) | ビュー座標の点・線・円 | 再投影後に近い線分へ吸着 (`resnap`, 許容 25 mm) |
| 測定の注記 (`MeasureNote.refs`) | `FaceRef` / `EdgeRef` (名前付き) | `src/measure/notes.ts` の `resolveNote` (mbd/resolve と同じ解決)。再構築後にカーネルで再測定、外れたら参照切れ表示と修復 |

インデックス (`#face:n`) は使っておらず、**位置の幾何学的な一致** だけで追跡していた。

### 参照が外れる・取り違える場面
- **寸法の大きな変更**: 押し出しの長さや幅を大きく変えると、絶対位置も正規化位置もずれ、別のエッジに付く、または「参照エッジが見つかりません」になる。
- **上流への挿入**: 参照位置の近くに穴やボスを追加すると、新しくできたエッジのほうが近くなり取り違える。
- **パターンの個数・間隔の変更**: 同じ形のインスタンスが並ぶため、位置がずれると隣のインスタンスに付く。
- **面上のスケッチ**: 面が動いてもスケッチ平面は動かない。
- **図面寸法**: 近くの線へ吸着するため、穴の移動や外形変更で別の線に付く。
- **黙って付け替わる**: どの場合も最も近い候補を選ぶだけで、取り違えても利用者に知らせない。

## 2. 設計

### 2.1 名前の付け方 (`src/kernel/naming.ts`)
各フィーチャの評価後、新しいボディの面・辺に履歴に基づく名前を付ける (WeakMap で形状に添付)。

| 由来 | 面の名前 |
|---|---|
| 押し出し | `<id>:start` / `<id>:end` (端面)、`<id>:side:<スケッチ要素 id>` (側面) |
| 回転・スイープ | `<id>:side:<スケッチ要素 id>`、端面 `<id>:start` / `<id>:end` |
| 穴 | `<id>:wall:p<k>` (穴壁)、`cbwall` / `cs` / `floor` (座ぐり・皿・底) |
| パターン | 元の面の名前 + `@<パターン id>.<番号>` |
| フィレット・面取り | `<id>:blend(<元のエッジ名>)` |
| シェル・厚み付け | `<id>:offset(<元の面>)` |
| その他の新しい面 | `<id>:gen(<隣接する継承面の名前>)` |
| 同名が複数 | 末尾に `~1`, `~2` … (並びが最も広がる方向の位置順) |

- **継承**: 結果の面が入力ボディ・ツールの面と同じ曲面 (平面・円筒・円錐・球・トーラスは解析的に比較、自由曲面は境界上の点の距離) にあれば、その名前を受け継ぐ。OCC の `BRepAlgoAPI::Modified()` と同じ情報を幾何学的に求める方式で、replicad がビルダを公開しない演算 (フィレット・シェル・抜き勾配など) にも同じ仕組みで効く。
- **辺の名前**: `E[<面A> | <面B>]` (両側の面の名前を並べたもの)。
- **スケッチ要素 id**: スケッチのプロファイル (`LoopSeg`) に元の要素 id (`src`) を持たせ、側面の名前に使う。寸法を変えても要素 id は変わらない。

### 2.2 解決 (`src/core/naming.ts` の `resolveNamed`)
保存された参照は、従来の幾何情報に加えて `name` を持つ。解決の順番:
1. 名前が完全に一致 (確信度 1)
2. `~k` を除いた名前が一致 → 幾何で選択 (0.8〜0.95)
3. 部分一致 (エッジなら同じ面を共有、面なら同じフィーチャ由来) → 幾何で選択 (0.6)。同点の候補が複数なら **曖昧** として外れ扱い
4. 名前なし (旧データ) は従来の幾何スコア (確信度 0.5 以下)
5. どれも許容範囲外なら **外れ** (lost)

外れ・曖昧の場合はカーネルが `RefBrokenError` を投げ、`RebuildResult.brokenRefs` に候補 (最大 5 個) と理由を返す。

### 2.3 UI
- 再構築後、外れた参照があればフィーチャ名とメッセージを通知。
- ブラウザの右クリック →「参照を修復」: その直前の形状で候補をハイライトし、クリックした面・辺で参照を置き換える (`src/commands/repairRef.ts`)。
- 面上のスケッチは `SketchFeature.faceRef` を持ち、カーネルが面を解決して平面を移動 (`planeFace`)、結果の平面を書き戻す。

### 2.4 既存データの移行
- 旧ドキュメントの参照には `name` がない。読み込み後の最初の再構築で従来の幾何スコアで解決し、`updatedRefs` で名前付きの参照が書き戻される (保存すると新形式)。特別な変換処理は不要。
- アセンブリ拘束は解決時に名前を補って保存し、図面寸法は表示時に 3D エッジの名前 (`GRef.topo`) を付ける。

## 3. 適用範囲

| 対象 | 状態 |
|---|---|
| フィレット・面取り・溶接のエッジ | 対応 |
| シェル・抜き勾配 (中立面含む)・厚み付け・プレス/プル・ねじ・分割 (面) | 対応 |
| 面上のスケッチ平面 (スケッチ作成・穴の配置) | 対応 (平面が面に追従) |
| パターンのシード | id 参照のため不要。パターン後の面・辺はインスタンス番号付きの名前 |
| アセンブリ拘束の面・辺 | 対応 (`src/assembly/toporef.ts`) |
| 図面寸法の付加先 | 部品図面の投影ビューで対応 (`src/drawing/toporef.ts`)。断面図の切断線・アセンブリ図面は従来の吸着のみ |
| PMI | 対応 (`src/mbd/resolve.ts`) |
| サーフェス系フィーチャのエッジ参照 | カーネル内の同じ解決処理を使用。ただしサーフェスボディ自体には名前を付けていない (幾何で解決) |
| 測定の注記 | 対応 (段階 2、`src/measure/notes.ts`)。ボディ単位・アセンブリのコンポーネント単位の注記は番号・id で参照 |

## 4. 既知の制限
- 名前の継承は曲面の一致で判定するため、同一平面に乗る別フィーチャの面が融合されずに残る場合は、外接箱の包含関係で由来を決める。
- 同名面の番号 (`~k`) は位置順なので、分割された面の並びが入れ替わるような編集では番号が入れ替わることがある (幾何で補正)。
- ロフト・フレーム・刻印・コイル・リブ・取り込み形状のツール面は種類 + 位置順の名前 (スケッチ要素との対応なし)。
- 図面寸法の点参照は辺の端点 (a/b) を記録するため、辺の向きが反転すると反対側の端点に付く可能性がある。
